# Тест-план: SauceDemo

**Версия:** 1.0  
**Цель:** провести функциональное и регрессионное тестирование пользовательского потока покупка на сайте [saucedemo.com](https://www.saucedemo.com/)  
**Автор:** Влад xDefox  
**Дата:** 2026-10-10

## 1. Объект тестирования

Веб-приложение «SauceDemo» — пример интернет-магазина для демонстрационных целей.

## 2. Область тестирования

В рамках данного плана покрываются:
- Авторизация
- Просмотр/фильтрация каталога
- Добавление/удаление товара в корзину
- Корзина
- Оформление заказа (Checkout)
- Базовая навигация

## 3. Область НЕ тестирования

- Платёжные системы
- Админка
- Многоязычность (кроме общих проверок)
- Производительность (не планируется)

## 4. Среда тестирования

- **ОС:** Linux
- **Браузер:** Chrome (тестовый)
- **Тестовые данные:** стандартные логины (`standard_user`, `locked_out_user`, `problem_user`, `error_user`, `visual_user`), пароль `secret_sauce`

## 5. Тест-дизайн

- **Эквивалентные классы:** валидные/невалидные креды, разные пользователи, товары в каталоге
- **Граничные значения:** пустые поля, мин/макс объём корзины (0 и все товары)
- **Позитивные и негативные сценарии**

## 6. Уровни и виды тестирования

- Функциональное
- Smoke-тестирование
- Регрессионное (по ключевым сценариям)
- Тестирование UI
- Кросс-браузерное (при необходимости)

## 7. Критерии входа/выхода

**Вход:** доступ к сайту открыт, нет блокирующих факторов  
**Выход:** основные пользовательские сценарии пройдены, критичные баги зафиксированы или закрыты, отчёт подготовлен

## 8. Риски

- Поведение `problem_user` намеренно отличается от ожидаемого — легко спутать баг с «особенностью»
- Пользователи с проблемами не позволяют выполнить полный позитивный сценарий

## 9. План работ

| Этап | Задача |
|---|---|
| 1 | Подготовка чек-листов ([checklists/](../checklists/)) |
| 2 | Написание тест-кейсов ([test-cases/](../test-cases/)) |
| 3 | Прогон по чек-листу |
| 4 | Фиксация баг-репортов ([bug-reports/](../bug-reports/)) |
| 5 | Подведение итогов |

## 10. Приоритеты

| Приоритет | Описание |
|---|---|
| P0 | Блокирует основной флоу (логин, оформление заказа) |
| P1 | Серьёзное отклонение от ожидаемого, workaround сложный |
| P2 | Несущественный UI/текст |
| P3 | Оптимизация/микродефект
